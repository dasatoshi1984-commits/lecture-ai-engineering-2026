## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - app/tools.py の search_glossary の docstring を 1 か所だけ変えた。
    - 変更前：query には調べたい用語を 1つだけ入れる（例 : "LoRA" ）。
    - 変更後：query には調べたい用語をまとめて入れる（例 : "LoRA QLoRA" ）。
  - INSTRUCTIONS など他の部分は変えていない。
  - 同じ質問「LoRA と QLoRA の違いは？」を、変更前後で --trace 付きで実行して比べた（変更前は 2 回実行し、2 回ともツールの呼ばれ方は同じだった）。
  - trace では検索結果が途中で省略されるため、変更後の query「LoRA QLoRA」で何が返るかを、search_glossary を直接呼んで確かめた。
- 結果：
| 項目 | 変更前 | 変更後 |
|---|---|---|
| ツール呼び出し | search_glossary('LoRA')、search_glossary('QLoRA') の 2 回 | search_glossary('LoRA QLoRA') の 1 回 |
| tool_calls | 2 | 1 |
| requests（LLM を呼んだ回数） | 2 | 2 |
| 入力トークン | 1,198 | 895 |
| 出力トークン | 192（1 回目は 184） | 218 |
| 目安の料金（cost） | 0.0008394 ドル | 0.0008135 ドル |
| 検索で返った用語 | LoRA と QLoRA（別々の検索で取得） | LoRA と QLoRA（1 回の検索で両方取得） |
| 回答 | 用語集の定義に沿って違いを説明し、最後に「関係する回：第2回」が付いた | 同様に両方の定義をもとに説明し、「第2回」が付いた |
- 気づき・疑問：
  - docstring の 1 文（例も含めて）を変えただけで、モデルは用語をまとめて 1 回で検索するようになった。モデルはツールの説明文を読んで、呼び方や引数を決めていることが確かめられた。
  - まとめて検索しても LoRA と QLoRA の両方の定義が返ったので、この質問では回答に必要な情報は減らなかった。ツールの呼び出しが 1 回減り、入力トークンも約 300（約 25%）減った。
